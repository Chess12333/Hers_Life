# 只读记忆查看

本功能可独立合入，不要求采用 B/C/D 或其他功能。

## 怎么使用

更新实际由 DSH `link:` 引用的 core-memory 源码，重启 DSH 并刷新网页。打开设置，进入 **记忆查看**。需要宿主的 webServer 和网页设置服务；没有网页服务时原有记忆工具照常工作，只是这个页面不能使用。

- 按标题、标签或编号筛选；状态可选生效、候选、已被取代、已作废。每页最多 25 条。
- 点一条，查看来源类别、创建/更新时间、最近确认、原文件位置和笔记正文。
- 替代或合并来源存在于当前库中时可点击跳转；找不到时明说没有找到，不伪造内容。
- 手工修改笔记后点“刷新”查看。没有后台轮询，也不会向模型发起处理。

没有来源标注的旧笔记显示“来源未知”；没有状态的旧笔记按现有插件规则视为生效，并明确提示“未标注”。界面里的“用户明确说的 / AI 推断”等是文件原有类别，不是工具对真实性的新背书。正文是保存的笔记，不承诺有原始聊天逐字证据。

## 数据和退出

读取现有 `<DSH_HOME>/memory/notes/*.md`，显示的 `memory/notes/...` 相对该 DSH 数据目录。已带 `deleted: true` 的文件不展示。列表不含正文，点开才返回正文；无法读取的文件会提示列表不完整。它不会修改笔记、重建索引或写回标签（插件原有启动逻辑保持不变）。

直接撤回本功能提交即可去掉页面，原记忆不需要迁移或恢复。原有共享范围、人格与记忆政策保持原样。不包含编辑、隔离、自动画像或删除全部索引/日志。

## 验证

```
node dsh-ming-core-memory/qa-inspector.mjs
node --check dsh-ming-core-memory/lib/client.js
```

合成文件验证列表、未知来源、旧记录、关系、正文、墓碑、路径限制与只读性。本地 Node 26.7.0、React 18 与 Edge 预览已验证搜索、状态筛选、关系点击及 390 像素布局。未宣称已支持未经验证的宿主版本；朋友需确认设置页能出现、打开笔记后字段符合自己的文件。
